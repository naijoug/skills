# Create or revise a plan

Define the observable outcome and meaningful exclusions. Map the relevant current
modules and reusable parts, citing actual paths/symbols. Split work by dependencies
and verifiable outcomes rather than imposing a fixed milestone count.

A useful plan contains:

- Goal and success criteria.
- Current state with facts separated from assumptions.
- Ordered tasks: outcome, affected paths/symbols, dependency and verification.
- Material risks, unresolved decisions and rollback where applicable.

Use the project's document convention; otherwise a requested file can use
`docs/plans/YYYY-MM-DD-topic.md`. Preserve an existing plan's useful context when
revising it. Routine uncertainty can be a stated assumption; do not turn every
open question into a blocking interview.
