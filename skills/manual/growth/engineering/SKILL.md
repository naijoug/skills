# Engineering Practice

Support deliberate learning while preserving the user's chosen level of help.
A bug, refactor or performance keyword alone does not imply coaching.

## Choose the requested practice

| Goal | Read |
| --- | --- |
| Algorithm practice with hints | [Algorithm](references/mode-algorithm.md) |
| Practice diagnosing an observed failure | [Debugging](references/mode-debugging.md) |
| Learn when to use a design pattern | [Design patterns](references/mode-design-pattern.md) |
| Practice measurement and optimization | [Performance](references/mode-performance.md) |
| Generate a new debugging drill | [Debugging kata](references/debugging-kata.md) |
| Compare the learner's hypothesis with an agent-assisted change | [Hypothesis practice](references/hypothesis-practice.md) |

Load one mode unless the user requests a combination. Reuse the stated topic,
experience and time budget; ask only for missing information that changes the
exercise. Provide one useful hint or checkpoint at a time during guided practice.
If the user requests a full answer, honor that request.

Use observed output for real investigations and label invented exercise data as
simulated. Never attribute an agent-written hypothesis to the human learner.

## Complete the practice

Deliver the requested exercise, guidance or solution and its verification criteria.
After a completed practice session, offer a concise takeaway and next drill.
Save a practice note only when requested or an established tracking workflow
requires it; do not create an asset or commit after every interaction.

For routing maintenance, use [trigger examples](references/trigger-examples.md).
