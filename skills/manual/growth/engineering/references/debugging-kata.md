# Debugging kata

Choose a learning objective, difficulty and failure mechanism that fit the request.
Build a solvable exercise with simulated code/logs/tests, realistic symptoms and
only enough noise to train investigation. Check that the evidence supports the
intended diagnosis; if executable files are requested, run the reproduction in
an isolated workspace.

Deliver the learner prompt, available evidence, constraints and success criterion.
Offer hints from broad direction to a concrete probe. Keep the root cause and
answer key out of the initial response unless the user requests them. A heading
that says "hidden answer" does not hide a solution printed in the same response.

On reveal, explain the mechanism, smallest fix and regression check. For a real
incident, use the actual evidence and task workflow rather than inventing a drill.
